# LaTeX 公式粘贴

把带 LaTeX 的文字粘进思源，公式直接变成思源公式。

从 ChatGPT、Claude、arXiv、PDF、Typora 复制内容时，公式往往写成 `\(E=mc^2\)`、`\[...\]` 或者 `\begin{equation}...\end{equation}`。这些写法思源不认，粘进去就是一串乱码似的反斜杠。这个插件在粘贴的那一刻把它们换成思源的 `$...$` / `$$...$$`，剩下的交给思源自己解析。

## 转换对照

| 粘贴进来的写法 | 转换结果 | 说明 |
| --- | --- | --- |
| `\(E=mc^2\)` | `$E=mc^2$` | 行内公式 |
| `\[ E=mc^2 \]` | `$$` 块 | 独占一行时转块级 |
| `由 \[x=1\] 可得` | `由 $x=1$ 可得` | 夹在文字中间时降级为行内，不打断段落 |
| `\begin{equation} … \end{equation}` | `$$` 块 | 保留环境名，KaTeX 认得 |
| `\begin{align} … \end{align}` | `$$` 块 | 同上，矩阵、多行推导都能用 |
| `$x^2+1=y$` | `$x^2+1=y$` | 已经是思源语法，内容不动；插件做的是把 HTML 降级掉，让思源真的去解析它 |
| `$$ … $$` | 原样保留 | 已经是公式，不会二次包裹 |

## 反向：从思源复制出去

思源自己的复制会把公式变成**不带 `$` 的裸 LaTeX**（比如 `d\lambda=dA(z)dA(\zeta)`），粘到 Obsidian、Typora 这类软件里就只是一串源码，不再是公式。

打开「复制出去时转成 Markdown」后，从思源复制含公式的内容时，插件会把公式还原成带定界符的标准 Markdown：

| 思源里 | 复制出去 |
| --- | --- |
| 行内公式 `dA` | `$dA$` |
| 块级公式 `E=mc^2` | `$$` 块 |
| 质能方程 **E=mc²** 很著名 | `质能方程 **$E=mc^2$** 很著名` |

几个细节：

- **只处理含公式的选区。** 没有公式时完全不插手，思源原生的复制行为一点不变。
- **复制出去的是纯文本层的 Markdown。** 粘回思源时思源会按 Markdown 语法重新解析，公式和结构都还在；粘到 Obsidian / Typora 拿到的也是同一份。
- 从渲染过的网页复制时，如果纯文本里的 `$` 已经被吃光，插件会尝试从 KaTeX / MathJax 的 `<annotation>` 里把 LaTeX 捞回来。
- 思源的「复制富文本」会把完整块结构塞进 `text/html` 的 base64 注释里，外层 HTML 反而是简化版。插件会翻进注释去取 `data-content`——选区内有几个块就有几条注释，**全部都会解析**。

### 结构也会一起转换

思源用 `<div data-type="NodeList">`、`NodeHeading` 这类自定义标签表达结构，而 Turndown 只认标准 HTML 标签。不翻译的话，复制出去的列表、标题、引用会**全部退化成没有标记的纯文本段落**。插件会先把它们换成标准标签：

| 思源里 | 复制出去 |
| --- | --- |
| 无序列表 / 有序列表 | `- 项` / `1. 项`，嵌套自动缩进 |
| 有序列表不从 1 开始 | 保留起始编号（`3.` `4.`） |
| 列表项里有两段文字 | 第二段另起一段并缩进，不会粘成一句话 |
| 任务列表 | `- [ ]` / `- [x]` |
| 标题 h1–h6 | `#` … `######` |
| 引用块 | `> ` |
| 引述块（Callout） | `> `（Markdown 没有对应语法，降成引用块最接近） |
| 表格 | GFM 表格（单元格里的段落不会撑破表格） |
| 代码块 | ` ```lang ` 围栏，**块里的空行原样保留** |
| 分割线 | `---` |
| 加粗 / 斜体 / 行内代码 / 删除线 | `**粗**` / `*斜*` / `` `码` `` / `~~删除~~` |
| 链接 | `[文字](地址)`，地址取自思源的 `data-href` |
| 标签 | `#标签#` |
| 块级公式落在列表项里 | 照常输出 `$$` 块，并且跟着列表缩进，不会把列表撑断 |
| 块级公式落在引用块里 | 每行都带 `> `，公式留在引用里 |
| 块级公式落在表格单元格里 | 自动降级成 `$…$` 行内，否则整张表会被换行撑碎 |

### 复制时用哪个入口

| 操作 | 结果 |
| --- | --- |
| **选中文字 → 右键 → 「复制为 Markdown（含公式）」** | ✅ 最顺手 |
| **顶栏的复制图标** | ✅ |
| **点块图标 → 「复制为 Markdown（含公式）」** | ✅ |
| 「设置 → 快捷键」给「复制为 Markdown（含公式）」绑一个键 | ✅ |
| `Ctrl+C` | ❌ 拦不住。思源会 `preventDefault` 后用 Electron 异步写系统剪贴板，等它写完，插件改过的数据已经被覆盖了 |
| 菜单「复制富文本」 | ❌ 同上，而且更彻底，完全不经过浏览器事件 |

选中内容右键，在菜单**末尾的「插件」子菜单**里会多出一项「复制为 Markdown（含公式）」。

> 为什么在子菜单里：思源从 v2.9.4 起规定，插件通过 `open-menu-*` 注入的菜单项统一收纳进「插件」子菜单，不直接出现在顶层，免得污染原生菜单结构。

**只在选中的内容里确实有公式时才出现**，平时右键不会多这一条。

> 快捷键默认没绑，因为 `Ctrl+Shift+C` 是思源内置的「复制块引用」（会得到 `((块ID "锚文本"))`），`Ctrl+Alt+C` 也不保证干净。想要快捷键就自己去设置里绑。

### 「复制纯文本」还是「复制富文本」

如果只是想在插件不生效的时候手动救一下：**选富文本**。纯文本那一层只有渲染后的字符流，公式的分式和上下标全被压平成一串（`∂Pf∂z̄j` 这种），信息不可逆；富文本带 HTML 层，里面才有 `data-content`。

## 安装

### 从集市安装

思源 → 设置 → 集市 → 搜索「LaTeX 公式粘贴」→ 安装 → 启用。

### 手动安装（开发用）

1. `npm install && npm run build`
2. 把 `dist/` 下的所有文件（`index.js`、`index.css`、`plugin.json`、`i18n/`、`icon.png`、`preview.png`）复制到
   `<思源工作区>/data/plugins/siyuan-latex-paste/`
3. 打开思源 → 设置 → 集市 → 已下载 → 启用「LaTeX 公式粘贴」

> 工作区目录在思源里可以这样找：设置 → 关于 → 工作空间。注意不是软件的安装目录。

### 开发模式

1. 把 `.env.example` 复制成 `.env`，填上工作区路径：

   ```
   SIYUAN_WORKSPACE=C:/Users/你的用户名/SiYuan
   ```

2. `npm install`
3. `npm run dev` —— 产物会直接构建到 `<工作区>/data/plugins/siyuan-latex-paste`，改代码自动重建，在思源里刷新插件即可看到效果。

## 设置项

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 启用公式转换 | 开 | 总开关 |
| 保留富文本格式 | 开 | 有公式时把 HTML 转成 Markdown 再粘贴，加粗、列表、链接都能保住；关掉后只处理纯文本粘贴 |
| 行内公式 `\( … \)` | 开 | 转成 `$ … $` |
| 块级公式 `\[ … \]` | 开 | 转成 `$$ … $$` |
| LaTeX 环境 | 开 | `equation`、`align`、`gather` 等环境转成 `$$ … $$` |
| Markdown 公式 `$ … $` | 开 | 剪贴板里已经写成 `$x^2+1=y$` 时也要让思源按公式解析 |
| 复制出去时转成 Markdown | 开 | 从思源复制含公式的内容时补回 `$` 定界符，别的 Markdown 软件才能当公式用 |
| 裸 LaTeX | 关 | 没有定界符的公式按整行识别。实验性，可能误判，默认不开 |
| 调试日志 | 关 | 控制台输出每次粘贴的处理过程，加载时弹一条提示。平时不用开 |

## 不管用时怎么排查

**1. 目录名必须和 `plugin.json` 里的 `name` 完全一致。**

比如 `name` 是 `siyuan-latex-paste`，目录就必须是 `<工作区>/data/plugins/siyuan-latex-paste`。名字对不上，思源不会加载它——这是最常见的翻车点。

**2. 确认插件真的加载了。**

打开设置里的「调试日志」，重启后在插件设置页里能找到这个开关。打开后插件加载完成会弹一条「LaTeX 公式粘贴：已加载」，粘贴时控制台也会逐条打印处理过程。没看到这条，说明插件压根没起来：检查目录名、重启思源、确认装的是你当前正在用的那个工作区（思源支持多工作区，插件是按工作区装的）。

**3. 看控制台。**

思源里按 F12 打开开发者工具 → Console，粘贴时会看到：

```
[latex-paste] 收到粘贴 { textPlain: "...", textHTML: "...", plain: {...}, html: {...} }
[latex-paste] 事件总线：改写载荷 {...}
[latex-paste] DOM 兜底：改写剪贴板 {...}
```

没有任何输出 = 插件没检测到公式，或者插件没加载。

**4. 公式的 `$` 莫名其妙没了？先看「收到粘贴」那一条。**

`textPlain` 是复制来源真正给你的纯文本。如果里面**已经没有 `$`** 了，说明是来源把公式渲染掉之后才放进剪贴板的——这种情况下插件只能尝试从 HTML 里的 KaTeX / MathJax 标记捞回 LaTeX，捞不到就没有了。换个地方复制（比如直接在源码模式下复制）就好了。

## 三条通道

插件同时走了三条路，互相兜底：

- **事件总线（粘贴）**：思源官方的 `paste` 钩子，能拿到 `protyle`，判断最准。但老版本思源（3.8.0 之前）替换载荷有 bug。
- **DOM 捕获（粘贴）**：在捕获阶段直接改写 `clipboardData`，不依赖思源版本。缺点是拿不到 `protyle`，只能靠 DOM 判断上下文。
- **DOM 捕获（复制）**：从思源往外复制时把公式还原成带 `$` 的 Markdown，只在选区里真的有公式时才接管。

粘贴的两条都生效也不冲突，转换是幂等的。

## 行为细节

- **代码块和行内代码不动。** 在代码块里粘贴，或者在正文里写 `` `\(x\)` ``，都不会被改。
- **思源内部复制粘贴不处理。** 从思源另一个文档复制过来时，公式本来就是公式（走 `siyuanHTML` 通道），插件直接放行。
- **带图片/附件的粘贴不接管。** 避免改动载荷时把文件弄丢。
- **转换是幂等的。** 同一段内容重复粘贴不会套娃。
- **已有 `$$` 公式不重复包裹。**

## 已知限制

- PDF 复制出来的内容，有时公式被拆进一堆 `<span>` 里（每个字符一个标签）。这种情况插件会退回纯文本处理，公式本身仍然正确，但那一行的加粗之类的小格式会丢。
- 极少数网站用图片或 MathML 表示公式，那种情况没有 LaTeX 源码，插件无能为力。
- 需要思源 3.1.0 以上。3.8.0 以下走 DOM 兜底路径，3.8.0 以上两条通道都可用。

## 一点实现说明

思源给插件留了 `paste` 事件总线，插件可以 `preventDefault()` 之后通过 `resolve()` 回传改写过的剪贴板载荷。但剪贴板里只要带 `text/html`（网页、Word、ChatGPT 复制都有），思源就会优先走 HTML 分支，纯文本改写会被绕过去。

所以这里的做法是：检测到公式时，把 HTML 转成 Markdown、清空 `textHTML`、只把 Markdown 交给思源的 `Md2BlockDOM` 解析。公式是思源的原生 Markdown 语法，解析出来就是真正的公式节点，不是伪装的文本。

Turndown 会把反斜杠当 Markdown 转义符（`\frac` → `\\frac`），所以公式必须在转换前先抽成占位符，转完再还原。
